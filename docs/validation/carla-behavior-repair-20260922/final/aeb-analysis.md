# 최종 8회 시험의 AEB 판정 구분

기본 주행 1회·차량 정지 1회·회피 3회·보행자 정지 3회가 모두 통과했다. 기본 주행을 제외한 7회에는 정상 AEB 관측 파일이 있으며, **시험 구간에서 수집된 AEB 진단 800개 모두 `No Collision`, ERROR 0개, `decision=brake` 0개**였다. 이는 계획·제어 기능의 성공이며 AEB 긴급 제동 개입을 성공시킨 시험은 아니다.

| 시험 | AEB 진단 표본 | AEB ERROR / brake | 객체가 있는 예측 메시지 |
|---|---:|---:|---:|
| 차량 정지 1 | 258 | 0 / 0 | 506 / 506 |
| 보행자 정지 1 | 68 | 0 / 0 | 240 / 240 |
| 보행자 정지 2 | 82 | 0 / 0 | 259 / 259 |
| 보행자 정지 3 | 73 | 0 / 0 | 261 / 261 |
| 차량 회피 1 | 142 | 0 / 0 | 553 / 553 |
| 차량 회피 2 | 78 | 0 / 0 | 433 / 433 |
| 차량 회피 3 | 99 | 0 / 0 | 448 / 448 |

모든 관측에서 `use_predicted_object_data=true`, `use_pointcloud_data=true`, MPC 경로 사용이 확인됐고 콜백 오류는 0개였다. 이동 중 AEB의 MPC 경로·차량 footprint marker는 생성됐다. 반면 경로 위 충돌 후보 `mpc_objects`의 비어 있지 않은 점과 RSS 출력은 관측되지 않았다. 따라서 AEB가 위험 객체를 잡아 긴급 제동했기 때문에 정지한 것으로 해석하면 안 된다.

보행자 3회 모두 GT의 PEDESTRIAN 예측 객체가 계획으로 들어왔고 `run_out`, `obstacle_stop`, `road_user_stop` 정지 요인이 나왔다. 제동과 충돌 없는 정지의 근거는 이 계획 입력·출력 및 실제 차량 반응이다. LiDAR 검출기가 개선됐다는 근거는 없다. 같은 시험의 점군을 AEB와 같은 높이·voxel·0.15m 군집 조건으로 전방 영역에서 분석했을 때 최대 연결 군집은 각각 3·3·2점으로 최소 10점보다 작았다. 이 참고 계산은 정확한 MPC footprint crop이나 보행자 전용 ROI 전체 재현은 아니다.

기존 충돌 당시 AEB 후보·RSS 내부 기록이 없어 과거 미개입의 직접 원인을 하나로 확정할 수 없다. 희박한 LiDAR 입력과 실제 재현된 첫 궤적 점 손실 오류는 확인된 제약이다. 첫 점 오류는 수정 후 단위 시험 14/14가 통과했지만, 그것만으로 과거 충돌의 원인이나 독립적인 AEB 성능이 입증되는 것은 아니다.

분석은 관측기 `ros_s`를 시험 도구의 첫/마지막 주행 샘플 `ros_time` 구간으로 제한하여 준비·cleanup STOP을 제외했다. [기계 판독 분석](aeb-analysis.json)에 파라미터, 표본 수, 원시 JSON의 SHA256과 한계를 기록했다. 원시 관측은 `*_aeb.json.gz`로 무손실 압축해도 분석 도구가 자동으로 읽으며 SHA256은 압축을 푼 JSON 기준이다.
