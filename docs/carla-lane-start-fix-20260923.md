# Town05 회피 경로 수정과 VTD 비교

2026-09-23. [최초 진단](carla-route-block-20260923.md)의 차로 시작점 투영 오류를
일반 차선 변경과 avoidance-by-lane-change 양쪽에서 수정했다. CARLA의 현재
사용자 경로를 유지한 채 정지 차량 회피, 원래 차로 복귀, 다음 우회전을 확인했다.
단, **한 번의 정상 배속 연속 성공 시험은 아니다**. 회피·복귀 후 경로 발행 지연으로
정지했고, 우회전은 같은 위치에서 0.5배속으로 이어서 검증했다.

## VTD와 달랐던 이유

VTD와 CARLA의 기존 회피 모듈 소스는 같았다. VTD 기능이 변환 과정에서 빠진 것이 아니다.
CARLA 현재 왼쪽 lanelet 16629는 약 787m로, 시작점이 차량 뒤에 있다.
앞뒤를 잘라 만든 reference path에 이 점을 투영하면 이후 경로 구간으로 잘못 붙어
전방 약 235m로 계산된다. 장애물은 약 10m 앞이므로 옆 차로를 후보에서 제외했다.

`calc_distance_to_lane_start`는 **전체 현재 차로 시퀀스** 위의 부호 있는 거리를 사용한다.
일반 차선 변경과 회피 후보 선별이 이 함수를 공유한다. 실제로 앞에서 시작하는
차로의 양수 거리와 차로 정보가 없을 때의 거부 동작은 유지한다.
VTD에도 긴 차로가 있으므로 모든 VTD 차로가 짧아서 동작했다고 일반화할 수는 없다.

| 기록 재생 | 수정 전 | 수정 후 |
|---|---|---|
| VTD의 기존 성공 장면 | LEFT, valid=1, safe=1, 경로 1개 | 동일; prepare=1.5s, shift=8.84836s도 동일 |
| CARLA 현재 정지 장면 | valid=0, 경로 0개 | valid=1, LEFT 경로 36개, safe=0 |

CARLA의 `safe=0`은 후보 누락과 별개다. 해당 기록에는 왼쪽 뒤 약 84m에서
약 45km/h로 접근하는 차량이 있어 RSS 충돌 검사가 진입을 거부했다.
안전 기준, 충돌 검사, 차선 연결, 지도, 횡단보도와 정지선은 이번 수정으로 바꾸지 않았다.
VTD 결과는 보관된 입력을 실제 모듈에 넣은 재생 검사이며 VTD 시뮬레이터 재주행은 아니다.

## 실제 CARLA 주행

- 같은 Town05 world, 전방 정지 차량 actor 163, 사용자 목적지와 16개 route segment 유지.
- 초기 Autoware 재시작으로 ego만 1040에서 2403으로 교체했다. 이후 검증 중 순간이동,
  ego autopilot, 배경 객체 삭제를 사용하지 않았다. 차량 76대(ego 포함), 보행자 250명 유지.
- 첫 시도에서는 경로가 생겨도 차량이 출발하지 않았다. 내리막 경사 보상 이후 제어 가속도가
  약 -0.48m/s²였고 저속 적분은 꺼져 있었다. CARLA 전용 PID 설정에서
  `enable_integration_at_low_speed=true`, `max_i_effort=1.0`을 적용했다.
  기존 적분 대기시간과 적분 활성화 조건은 유지한다. VTD PID 설정은 변경하지 않았다.
- 적용 후 road 37/lane 4 → lane 3 → 장애물 통과 → lane 4 복귀를 확인했다.
  충돌 센서 기록 0건, 표본에서 계산한 주변 차량/보행자 2D 외곽 최소 간격 약 0.833m.
  최고 속도 약 7.57km/h. 시험 속도 상한은 15km/h였다.
- 그 뒤 `/planning/trajectory` 5Hz 경고가 자율주행 진단을 WARN으로 올려 MRM이 정지시켰다.
  일부 프레임의 behavior planner 처리 시간은 약 219ms였다. 진단/MRM을 해제하지 않았다.
- 계속 시험할 때만 CARLA `fixed_delta_seconds`를 0.05 → 0.025로 바꿨다.
  bridge의 최소 wall tick 간격 0.05s는 유지해 시뮬레이션을 최대 0.5배속으로 진행했다.
  신호 정지와 재출발 후 우회전하여 junction을 벗어난 것을 확인했다. 추가 충돌 0건,
  최고 속도 약 9.24km/h. 두 시험 사이 STOP과 재개가 있었으므로 연속 성공으로 세지 않는다.
- 검증 후 STOP 확인, 시험 속도 상한 해제, `fixed_delta_seconds=0.05` 복구.
  최종 CARLA 위치 약 (28.756, -173.673), yaw 91.464°. 배경 교통 제어기는 실행 상태다.

**남은 한계:** 정상 배속의 많은 객체가 있는 장면에서 경로 발행 주기 저하가 남아 있다.
이번 결과는 회피 후보 계산 수정과 해당 장면의 기동 검증이며, 정상 배속 장시간 안정성이나
모든 경사에서의 종방향 제어 보정 완료를 의미하지 않는다.

## 빌드와 검사

```sh
docker build -f docker/carla/Dockerfile.lane-start-fix \
  -t selfcar-2026-carla:lane-start-fix-20260923 .
```

증분 이미지는 보존한 `selfcar-2026-carla:behavior-repair-20260922`를 기반으로 두 차선 변경
패키지를 다시 빌드한다. 전체 CARLA Dockerfile에도 두 패키지를 재빌드하도록 추가했다.
CARLA 전용 PID 파일은 이미지 설치 스크립트에서 launch 설정 위치에 복사한다.
이 머신의 `selfcar-2026-carla:local` 태그도 검증한 수정 이미지로 갱신했다.
검증 완료 당시 실행 컨테이너에는 수정 planner와 위 PID 파라미터를 적용했고,
최종 이미지의 차이는 주석 정리 및 같은 PID 설정의 시작 파일 반영이다.

거리 부호, 양쪽 차선, U자 경로의 잘못된 미래 구간 투영, 일반 차선 변경의 전체 차로 사용,
차로 정보 누락을 검사하는 gtest 4개가 통과했다. VTD/CARLA 기록 재생은 동일 입력으로
수정 전후 라이브러리를 각각 사용했다. 재생 실행 로그에 rcutils 로깅/type support 경고가
있지만, 위 표의 모듈 계산 결과와 경로 출력은 양쪽 실행에서 수집했다.
