# 교차로 출구의 차선변경 시작 위치

교차로 연결 차선에서 일반 도로로 진입하면서 옆 차선이 시작하는 경우에만 적용한다.
지도상의 연결 차선에 `turn_direction`(left/right/straight) 또는 유효한
`intersection_area`가 있고, 다음 일반 차선의 양쪽 시작점이 그 연결 차선의 끝점과
0.1 m 이내로 연결되어야 한다. 목표 차선도 같은 방향의 일반 도로이며, 안쪽 시작점이
요청 방향의 공통 출구 모서리와 연결되어야 한다. 일반 도로의 분기, 다른 교차로,
끊어진 차선, 반대 방향 차선은 이 조건에 해당하지 않는다. 위치 판단은 지도 정보에
기반하며 특정 지도나 lanelet ID를 하드코딩하지 않는다.

해당 목표에는 기존 10 m 후방 가상 확장을 적용하지 않는다. 일반 후보·Frenet 후보·
터미널 후보와 캐시/강제승인 후보 모두 변경 시작 위치가 출구를 지난 뒤가 되도록
검사한다. 현재 차선의 진행 거리를 기준으로 차량 뒤쪽 길이와 추가 0.5 m를 확보한다.
다른 구간의 기존 가상 확장, 준비시간, 충돌 검사와 후보 선택 규칙은 유지한다.

경계 정지 후 재계획도 출구 근처에서만 바뀐다. 출구가 최대
`max(target_lane_backward_overlap_length, vehicle_length)` 거리 안에 있고 후미 여유가
아직 확보되지 않은 경우, 실제 지도 차선으로 준비 구간을 만든다. 준비 길이는 최소
필요 길이와 그보다 2/5/10 m 긴 구간을 탐색한다. 현재 차량 위치·방향에서 현재 차선의
곡선을 따라 진행한 뒤, 그 지점에서 기존 저속 차선변경 생성기를 사용한다.
차선변경 길이 6–40 m와 기존 속도 샘플은 유지한다. 검사는 전체 준비·변경 구간의
조향 한계, 실제 차체 영역, 금지 경계, 정지 공간과 기존 충돌 조건에 적용한다.
출구 이후 충분히 진행했거나 일반 구간이면 기존 재계획 분기를 사용한다.

신호등/AEB/장애물 제외 조건과 최종 path optimizer의 경계 정지는 수정하지 않는다.
후보가 없으면 기존 정지를 유지한다. 이 변경은 교차로 출구에서 회피 목적의 차선변경
시작 위치도 늦출 수 있다. 그것은 같은 지형 조건에 대한 의도된 영향이다.

증분 빌드: `docker/vtd/intersection-exit.Dockerfile`.
