## 해결 대상

18:54:34 폴더 bag에서 18:55:33.456에 회피 RIGHT가 완료되는 같은 주기에
일반 `lane_change_left`가 시작됐다. 일반 LEFT가 실행되는 동안 exclusive 회피 모듈은
다음 바깥 차선 후보를 제출하지 못했다. 복귀 경로는 당장 이동하고 정지하는 데는
유효했지만, 약 25m 앞에 나란히 선 차량 앞으로 돌아가 다음 회피 공간을 소모했다.
당시 3차선에도 옆쪽 차량이 있었으므로 즉시 2→3 이동이 안전했다고 단정할 수는 없다.

## 바뀐 판단

- 일반 LEFT/RIGHT와 회피가 같은 planner node 안에서만 판단 문맥을 공유한다.
  `avoid_required` 및 기존 대상 분류를 통과하고 승인 거리 안에 있는 객체 UUID가
  회피 이유가 된다. 이유는 모듈 종료 후에도 공유되지만, 경로·RTC 승인·출발 위치는 저장하지 않는다.
- 현재 차선 유지와 각 합법적 후보 차선의 빈 종방향 구간을 비교한다.
  60m 이내, 현재 유지에서 최대 두 차례 / 첫 후보 이동 이후 한 차례의 추가 연결만 추정한다.
  인접 경계의 차선변경 허용 구간도 확인한다. 미래 곡선 경로를 여러 개 생성하지 않는다.
- 회피 후보는 대략적인 전진 가능 거리, 목적 차선 근접도, 이동 차선 수 순으로 탐색한다.
  전진 거리를 차량 길이 단위로 나눈 동일 점수 구간에서는 목적 차선 우선이다.
  한쪽 후보의 실패만으로 반대쪽 후보를 숨기는 별도 veto를 제거했다.
  기존 현재 차선의 지속 장애물·정체열·규제 요소 판정은 그대로 유지한다.
- 일반 **최종 복귀**가 여전히 관측되는 원래 장애물 앞으로 돌아가며,
  현재 차선을 유지할 때의 추정 전진 여유가 차량 한 대 길이 이상 더 좋고
  즉시 정지 여유도 비교 오차 1m 이내인 경우, 그 복귀 요청을 미룬다.
  이 1m는 선호도 비교 허용 오차일 뿐 실제 충돌검사·정지 마진을 줄이는 값이 아니다.
  승인 대기 중의 낡은 요청도 실행 전 재검사하고 종료한다.
- **중간 단계인 3→2 이동은 이 최종 복귀 억제에서 제외한다.**
  2→1의 미래 경로가 아직 없어도 3→2의 실제 경로가 기존 검사를 통과하면 진행할 수 있다.
- 이미 RUNNING인 경로는 이 선호도 때문에 취소하지 않는다.
  객체가 지나갔거나 사라짐, 이동 시작, route/map 변경, 시각 역행은 관련 문맥을 갱신한다.
  입력이 오래됐거나 지형 계산이 불명확하면 새 선호도를 적용하지 않고 기존 판단으로 돌아간다.
- 회피 SUCCESS 직후 그 모듈만 재조회에서 제외되는 한 주기에는 다른 모듈의 신규 실행도
  함께 보류하고, 완료된 모듈의 현재 유효 출력을 발행한다. 다음 planner 주기에는
  모든 후보를 함께 비교한다. 정지나 미래 복귀 경로를 기다리는 절차가 아니며,
  한 번의 `propagateFull()` 호출 안에만 존재하는 삭제 목록을 사용해 자동 해제된다.
  따라서 정적회피 모듈도 이 인계 빈틈에서 먼저 실행권을 가져가지 않는다.

## 유지한 것과 한계

`return_plan`의 최종 복귀 예약, 예약 위치 정지, 정지 후 handoff는 복원하지 않았다.
안전한 중간 이동의 승인에 최종 복귀 경로 존재를 요구하지 않는다.
장애물 군집을 하나의 충돌 박스로 합치지 않았다.

기존 실제 swept-footprint 충돌검사, predicted-path/RSS 검사, 곡률/감속 준비,
승인 거리 35m, 정적 확인 3초·움직였던 객체 정차 재판정 7초,
obstacle_stop 4.5m 및 차량 마진은 변경하지 않았다.
새 로직은 속도 상한이나 정지점을 추가하지 않는다.
기존 명시적 RTC 강제 승인 기능 자체를 제거한 것은 아니지만, 새 정책으로 미룬
승인 대기 요청이 이 기능을 통해 뒤늦게 시작하지 않도록 인계 시 재검사한다.

빈 구간 연결은 후보 **선호도 추정**이다. 조향·속도·후방 차량 때문에 그 연결이 실제로
불가능할 수 있다. 실제 안전성은 기존 경로 생성과 충돌검사가 계속 판단하며,
모든 장애물 배치에서 무정지 통과를 보장하지 않는다. 목적 차선으로의 중간 이동은
허용하므로 모든 형태의 왕복을 일괄 금지하는 정책도 아니다.

## 설정·빌드·확인

VTD `lane_change.param.yaml`의 `lane_change.tactical_selection.enable: true`로 활성화한다.
다른 환경에서 해당 설정을 지정하지 않으면 기본 비활성화다.

`docker/vtd/stepwise-lane-choice.Dockerfile`은 기준 이미지 위에서 behavior path planner,
lane change, avoidance-by-lane-change, external-request lane change 네 패키지만 재빌드한다.
새 공개 Parameters 레이아웃을 사용하는 세 모듈을 함께 교체한다.
브릿지와 planner common ABI는 변경하지 않는다.

단독 `test_corridor_choice.cpp`는 종방향 빈 구간, 동일 장애물로의 조기 복귀,
실선 이후 가상 연결 제외, 최종 경로 미확정 중간 이동, 문맥 해제와 unknown을 확인한다.
시나리오 자동 주행·전체 회귀시험은 수행하지 않는다.
별도 읽기 전용 컨테이너에서 이미지 파일 차이, 설정 보존 및 네 라이브러리 로딩을 확인한다.
실행 중인 Autoware/브릿지 및 실시간 파라미터는 변경하지 않는다.
