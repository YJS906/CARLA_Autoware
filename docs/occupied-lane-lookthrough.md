# 중간 차선 점유 시 바깥 차선 후보 탐색 (2026-09-10)

## 변경

`AvoidanceByLaneChange::getTargetLaneCandidates()`에서 차선 점유 여부를 후보 추가와
바깥 차선 탐색의 중단 조건에서 제거했다. 기존에는 바로 옆 차선이 점유되면 그 차선만
후보로 넣고 종료했고, 점유된 두 번째 이후 차선은 후보에 넣지도 않았다.

이제 `enable_direct_multi_lane_change: true`이면 바로 옆 차선이 점유되어도
같은 방향으로 연결된 바깥 차선들을 후보에 넣는다. 바깥 차선 자체가 점유되어도
차선 전체 점유가 아닌 실제 생성 경로의 안전 검사로 판단한다.

후속 복귀 검사도 함께 보완했다. 종전의 단일 `last_return_search_`는 옆 차선의
실패한 복귀 검사만으로 바깥 차선의 계산까지 매번 대기시킬 수 있었다. 이제 대기시간은
목표 차선별로 기록한다. 한 계획 주기에 새 복귀 검색은 최대 한 번만 수행하므로
기존 20 ms 협력적 계산 예산을 후보 수만큼 같은 주기 안에서 늘리지 않는다.
옆 차선을 검사한 주기에 바깥 차선이 보류되면, 옆 차선이 대기 중인 다음 주기에
바깥 차선의 복귀 검색을 시도한다. 보류만으로 그 후보의 대기시간을 갱신하지 않는다.
앞순위 후보를 다시 검사할 때 이미 확보한 바깥 차선 복귀 계획을 삭제하지 않으며,
재사용할 때는 기존 조건 일치와 정지 객체 충돌 검사를 계속 수행한다.

다음 조건은 바꾸지 않았다.

- 지도 라우팅 그래프의 합법적인 `left`/`right` 연결, 경로 소속 여부, 장애물 이전에
  진입 가능한 차선인지 확인. 실선 등 금지 경계와 중앙선을 임의로 넘지 않는다.
- 경로 생성·곡률, 예측 경로 및 정지 객체 충돌 검사, 필요한 복귀 계획 검사.
- 목적 차선 우선 순위와 첫 번째 완전히 안전한 후보를 찾았을 때 탐색 종료.
- 승인된 목표 차선 유지. 다중 차선 옵션이 꺼져 있으면 방향별 바로 옆 차선까지만 탐색.
- 승인 거리 35 m와 S자 기하학적 최소 길이 배율 0.5.

`empty_lane_check_forward_distance` / `empty_lane_check_backward_distance`는
기존 파라미터 호환성을 위해 남겨 두었으나 이제 DEBUG 점유 로그 범위에만 사용한다.
DEBUG 로그를 껐을 때 불필요한 차선 점유 검사가 실행되지 않도록 호출도 로그 안으로 옮겼다.
